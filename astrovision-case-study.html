AstroVision AI

An end-to-end astronomical image classification system that turns uploaded imagery into model-ready tensors, runs EfficientNet-B0 inference, and returns an interpretable prediction through a FastAPI service.

01 · Overview

From raw space imagery to a structured prediction.

Astronomical images vary in dimensions, orientation, color, and visual clarity. A useful classifier therefore needs more than a trained model: it needs a reproducible path from upload to preprocessing, inference, confidence scoring, and presentation.

AstroVision connects that complete path. A transfer-learned convolutional network performs the classification, while the API layer makes the model accessible through a practical web workflow and preserves reusable class mappings.

04 · Product capabilities

A complete model-to-interface workflow.

UPLOAD

Image-based prediction

Accepts a user-uploaded image, reads it with Pillow, and converts it to RGB before inference.

MODEL

Transfer learning

Adapts ImageNet-pretrained EfficientNet-B0 features to the project’s astronomical image classes.

DATA

Automatic class discovery

Scans leaf folders for labeled images and creates a saved class mapping for consistent training and inference.

API

Structured response

The FastAPI endpoint returns the predicted label and confidence as a simple JSON response.

TRAIN

Validation workflow

Tracks training and validation performance and saves the model state with the strongest validation result.

INFO

Scientific context

Organized metadata files cover astronomical groups including planets, stars, galaxies, nebulae, and comets.

05 · Engineering decisions

Challenges solved deliberately.

01

Limited domain-specific training data

Solution: Transfer learning starts from pretrained ImageNet features, freezes the feature extractor, and trains a replacement classification head for the detected classes.

02

Inconsistent source images

Solution: Images are converted to RGB, resized to 224 × 224, transformed into tensors, and normalized with the same values used by the pretrained model family.

03

Keeping labels aligned with weights

Solution: The training pipeline saves the discovered class order as JSON, and the inference service loads that exact mapping alongside the model weights.

04

Turning a notebook-style model into a product

Solution: Model loading and prediction are separated from FastAPI routing, allowing a web client to use the trained classifier through a focused `/predict` contract.

08 · Current limitations

Results need context.

  • Educational classifier, not a tool for professional astronomical research.
  • Predictions depend on the coverage and quality of the training dataset.
  • Confidence is a model score, not proof that a prediction is scientifically correct.
  • Evaluation metrics should be published before making comparative performance claims.
09 · Next steps

Roadmap.

  • Publish per-class precision, recall, F1 score, and a confusion matrix.
  • Add input validation and clear handling for unsupported or corrupted images.
  • Connect the organized scientific metadata to each prediction result.
  • Package model serving for a reproducible cloud deployment.
